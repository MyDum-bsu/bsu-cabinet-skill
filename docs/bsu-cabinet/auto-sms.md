# Авто-SMS через adb

Обычный `bsu-browser login` не обращается к adb. Авто-SMS включается отдельно и только с ранее сопряжённым телефоном, выбранным владельцем:

```bash
uv run bsu-browser login --sms adb --adb-serial <выбранное-устройство>
```

Вместо аргумента устройства подходит `ANDROID_SERIAL`. Команда ищет бинарник по `BSU_ADB`, PATH, затем `~/.local/platform-tools/adb` (`adb.exe` на Windows).

## Диагностика после явного выбора авто-SMS

- `adb devices -l` показывает активные соединения. Проверь именно выбранный телефон: `adb -s <устройство> get-state` должен вернуть `device`. Приложение не перебирает другие устройства.
- При смене Wi-Fi-порта посмотри `adb mdns services`. Для известного устройства нужен текущий адрес из `_adb-tls-connect._tcp`, не адрес сопряжения. После подтверждения, что это тот же телефон, выполни один `adb connect <текущий-адрес>` и снова проверь состояние. Не подключайся к первому найденному телефону.
- Если устройство не видно, владелец проверяет общую Wi-Fi сеть и «Беспроводную отладку». Новое сопряжение инициирует владелец. Код сопряжения вводится локально, не в чат.

## Что читает приложение

Запрос ограничивает телефон, время отправки формы и шаблон `Vash kod vxoda v CabinetBSU: NNNN`. Номер отправителя не фиксируется: он меняется. Коды из других сообщений, старые SMS и неподходящий формат не принимаются. Код не выводится, передача кода аргументом команды не поддерживается.

При недоступном телефоне используй видимое окно и ручной SMS. Если код уже запрошен, не запрашивай второй по тому же сбою. Авто-SMS ранее проверялся на Samsung S24 с уже настроенной беспроводной отладкой; это не проверка всех устройств и ОС.
