# Вход в кабинет БГУ

Требуются `bsu-browser`, Chrome и системное хранилище паролей ОС. Chrome ищется через `BSU_CHROME`, PATH или типовой путь ОС. `BSU_NO_PROXY=1` отключает прокси Chrome, если локальный прокси не достаёт кабинет. В checkout репо команды идут из каталога `bsu-cabinet` через `uv run bsu-browser`, в установленном комплекте — напрямую `bsu-browser` (или `.venv/bin/bsu-browser` из корня комплекта).

## Вход и первый запуск

1. Запусти `bsu-browser login`. **По умолчанию телефон не проверяется и не подключается.** Если текущий профиль без файла логина, команда сама открывает в Chrome локальную форму «Настройка входа». Владелец вводит логин и пароль **только там**. Успех настройки подтверждает CLI после записи в системное хранилище и файл `login`. Старые данные из `~/.bsu-agent` не подхватываются.
2. При запросе SMS владелец вводит код **на странице кабинета в Chrome** и нажимает «Подтвердить». Пароль и код не передавать в чат, параметры команды или логи. Успешный вход подтверждает переход CLI на `https://teacher-cabinet.bsu.by/PersonalCabinet`. Повторный вход — та же команда; при живой сессии кабинета SMS не понадобится.
3. `bsu-browser start` сам по себе запускает Chrome без окна. Для настройки и ручного SMS команда сама переводит **подтверждённо свою** headless-сессию в видимое окно до отправки SMS: своей считается только та, у которой и записанный процесс (точный аргумент `--user-data-dir`), и слушатель порта принадлежат комплекту; stale-метаданные и неизвестный владелец — отказ без подключения к чужому CDP, без остановки процесса и без SMS, с подсказкой про `BSU_PORT`. Без экрана — понятный отказ до отправки.

Для теста с нуля используй новый пустой `BSU_STATE_DIR` и свободный `BSU_PORT`. `bsu-browser setup` можно запустить отдельно; не копируй старый профиль, cookies или файл логина. Если владелец сам предпочёл терминал, `bsu-browser creds <login>` принимает пароль в защищённом вводе.

## Advanced: авто-SMS с выбранного телефона

Только если владелец явно попросил использовать ранее сопряжённый телефон:

```bash
bsu-browser login --sms adb --adb-serial <выбранное-устройство>
```

Вместо `--adb-serial` можно передать известное устройство через `ANDROID_SERIAL`. Одно наличие телефона или этой переменной не включает авто-SMS. Команда работает только с указанным устройством, не выбирает первое и не запускает сопряжение. Подробнее: [проверка adb и текущего адреса](../../../docs/bsu-cabinet/auto-sms.md).

Если выбранный телефон недоступен, продолжить ручным вводом можно только в видимом Chrome. Если SMS уже запрошен, используй тот же открытый диалог; команда не запрашивает второй код автоматически. Чтобы увидеть состояние входа, запусти `bsu-browser status`; ошибка доступа не означает успешный вход.
